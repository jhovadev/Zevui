# F3 — Standalone Zevui SDK and CSV Explorer extraction

Status: **implemented in patch; Zig 0.17.1 compilation is a required local gate**.
Baseline: F2 commit `0454e92`. Scope: source boundaries and package structure;
no new addons, no ZData repository changes, no package publication, no change
to public `zevui.zon` keys or Windows GUI subsystem behavior.

## Before → after

| F2 path | F3 path | Ownership |
| --- | --- | --- |
| `zevui/build.zig` | `framework/build.zig` | Zig SDK build API |
| `zevui/config.zig` | `framework/src/config.zig` | Pure typed configuration |
| `src/ui/**` | `framework/src/ui/**` | Reusable UI kit, including embedded SVGs |
| `src/main.zig` | `examples/csv-explorer/src/main.zig` | CSV application |
| `src/{csv,search,bench}.zig` | `examples/csv-explorer/src/` | CSV-only data handling |
| `src/app/**` | `examples/csv-explorer/src/app/**` | CSV app identity and embedded PNG |
| `examples/csv/build.zig` | `examples/csv-explorer/build.zig` | CSV correctness and benchmarks |
| F2 generator source `zevui/{build,config}.zig` | `templates/compat/zevui/{build,config}.zig` | Frozen generated-project output |
| F2 generator source `examples/minimal/main.zig` | `templates/compat/minimal/main.zig` | Frozen generated-project output |

All physical moves are performed using `git mv` in the preparation repository.
`framework/build.zig.zon` now declares an independent `.zevui` package with
paths and a fingerprint. The main application consumes it as a local path
dependency. The UI kit is injected as a real Zig module, not copied into CSV
Explorer. `framework/src/storage.zig` declares only capability/error types.

## Dependency boundaries

```text
root build.zig
  ├── @import("zevui")           [package build API; used by both apps]
  ├── b.dependency("zevui")      [framework module; local path]
  ├── b.dependency("dvui")       [one shared dvui_sdl3 module]
  ├── examples/csv-explorer/     [uses kit + ZData]
  └── examples/minimal/          [uses kit; no ZData]

framework/ ──> std only (core, tests, module registration)
framework/src/ui adapters ──> host-provided dvui module
CSV Explorer ──> Zevui SDK, DVUI, ZData
Initializr TS ──> templates/compat (temporary; deterministic F2 ZIP)
```

No SDK source references CSV, Initializr, registry or the user's ZData
algorithms. External module support is staged: F3 proves the local `.path`
dependency and separate package build; F4/F5 must replace it with a pinned
published URL/hash and test an **independent** generated Zig consumer.

### Why the Initializr keeps a compatibility template

F2's downloadable Zig output has SHA-256 golden fixtures. For F3, only the
repository's SDK and examples move. The template under `templates/compat`
retains F2's generated bytes, verified against Python's frozen oracle and the
Node TS generator. It is **not** another framework implementation to maintain:
no new features or changes should go there. F5 replaces its output with a
pinned public Zevui package and regenerates golden files under a reviewed ADR.

## Risks and reverse

- Zig package import/target handling and DVUI module sharing must be validated
  with `zig build` on the pinned 0.17.1 toolchain.
- External consumers still need SDK publication and URL/hash pinning; no
  remote URL is fabricated.
- Migrated embedded SVGs/PNG stay within their respective module source roots;
  do not embed resources outside those roots.
- Restore F2 with `git revert <F3-commit>` (after committing F3 separately).
  Before commit, use `git apply -R` only when it applies cleanly and no local
  edits would be lost. Preserve the current data and any uncommitted work.
- **Do not remove** `templates/compat` until F5 and new byte-for-byte tests.

## F3.1 Zig 0.17.1 build-module ownership hotfix

**Observed on Arch Linux (user test):** `zig build` failed before compiling
the apps with `framework/build.zig:1:1: error: file exists in modules
'@build' and 'framework'`. The original root `build.zig` imported the
framework package's build entry as a relative file and independently loaded
the same package from `.zevui = .{ .path = "framework" }`.

The root build now uses `const zevui = @import("zevui");` to refer to
the dependency's build API by its package/module name. This preserves the
independent package and its public runtime module. **Never combine**
`@import("framework/build.zig")` with the `.zevui` package dependency.

Acceptance on Zig 0.17.1:

```sh
just framework-check
just check
just minimal
just run-minimal
just run
```

Python structural checks cannot verify Zig's compile-time module graph.
Do not mark the Zig gates as passing until the commands above finish.
