# Zevui CLI — implemented in Zig

Source-owned component installer built with **Zig 0.17.1**. `src/main.zig` performs all commands, JSON parsing, SHA-256 verification, path checks, and file installation. It needs neither a DVUI backend nor a browser runtime.

The `build.zig.zon` package **fingerprint is permanent**. Zig 0.17.1
requires it; do not delete or regenerate it when publishing or bumping the version.

## Native executable (preferred)

```sh
cd packages/zevui-cli
zig build test
zig build -Doptimize=ReleaseSafe
./zig-out/bin/zevui list
./zig-out/bin/zevui init --project /path/to/zig-app
./zig-out/bin/zevui add calendar input checkbox --project /path/to/zig-app
./zig-out/bin/zevui doctor --project /path/to/zig-app
```

`zevui init` **does not create a new Zig application**. The target must already be a project with `build.zig` (for example, one generated by Zevui Initializr). Use `just components-cli-smoke` from the repository root for an isolated installation/integrity test; the smoke creates a temporary minimal Zig project and cleans it up automatically.

Build the single executable to use Zevui without npm, Bun, Node or Python. See `SKILL.md` for agent workflows.

## npm and Bun entry points (optional)

Once the maintainer publishes `@zevui/cli` to npm:

```sh
npx @zevui/cli@latest list
bunx @zevui/cli@latest init
bunx @zevui/cli@latest add calendar input checkbox
```

The `bin/zevui.mjs` file is **only a process launcher**. If a compatible prebuilt native executable is packaged, it invokes it. Otherwise, it calls `zig run src/main.zig ...`. Zig **0.17.1** must be installed and on `PATH` in that case. Nothing has been published by this patch, and no JavaScript CLI implementation is shipped.

The public `registry.json` follows the shadcn index schema; `registry-bundle.json` contains verified Zig sources and SHA-256 digests. A byte-identical generated mirror at `src/registry-bundle.json` is embedded by the native CLI because Zig 0.17.1 restricts `@embedFile` to the root module directory. It's offline and does not fetch or run remote code. Components are installed under `src/components/` (fixed alias for this version). `init` creates `zevui.components.json`; managed checksums are stored in `.zevui/components.lock.json`, compatible with the earlier Python installer. Local modifications, missing files, unsafe paths and unmanaged collisions block writes; `--dry-run` previews changes.

Maintainers: always regenerate both JSON copies with `node scripts/build-registry.mjs`, then verify with `node scripts/build-registry.mjs --check`, `zig build test`, and `npm pack --dry-run` before publishing. The build-registry script is development tooling, not part of the native runtime.
